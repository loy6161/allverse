## ① アクセサリーの複数付け（`av.ac`）

### 何が変わるか

いまは1人1つでした。

```json
"av": { "ac": "halo" }
```

これが、**`+` でつないだ複数**になることがあります。

```json
"av": { "ac": "wing+halo" }
```

### 決めたこと

| | |
|---|---|
| 区切り | **半角プラス `+`** |
| 最大 | **3つまで**（それ以上はこちらで切ります） |
| 順番 | **不定**。`"wing+halo"` と `"halo+wing"` は同じ意味 |
| 1つのとき | **いままでどおり `"halo"`**（`+` は付きません） |
| 無しのとき | **いままでどおり `"none"`** |
| 未知のid | **無視**してください（他のidは活かす） |

### なぜ「新しい項目を足す」ではなく「同じ項目に詰める」のか

**presence の契約（v=1）を触りたくないため**です。`ac` は文字列のままなので、
**形は1バイトも変わりません。版上げも要りません。**

### そちらが何もしなかった場合

`"wing+halo"` は**知らないid**として `none` 扱いになります（返答⑥で決めた通り）。
つまり**複数付けた人だけ、VRCではアクセサリー無し**に見えます。壊れはしません。

**1つだけ付けている人は今までどおり**なので、大多数は影響を受けません。

### お願い

**`ac` を `+` で分割して、それぞれ既存の処理にかけてください。** それだけです。

```
// 疑似コード
foreach (id in ac.Split('+')) { AttachAccessory(id); }   // 知らないidは無視
```

排他の考え方はこちらで揃えます（**メガネとサングラスは同時に付きません**）。
そちらで排他を作り込む必要はありません。

## ② ステージ登壇（★こちらは対応してほしいです）

### 何が変わるか

**管理人とVIPだけ、ステージの上に立てるようにします。**
イベント設定でON/OFFできるようにするので、常に起きるわけではありません。

その結果、**いままで客席の矩形の中にしか来なかった `x`/`z` が、その外に出ます。**

### 座標の範囲（VRCワールド座標・実測から換算）

| | いままで（客席） | 追加される（ステージ） |
|---|---|---|
| X | 約 **-234 〜 -196** | 約 **-224 〜 -204** |
| Z | 約 **-88 〜 -67** | 約 **-102 〜 -90** |

※ ブラウザ側の実測値（歩ける範囲 `minX:-13, maxX:25, minZ:-16.5, maxZ:5`／
ステージ前端 z=-18.07・背面 z=-30）を、既存の換算式
（`X = -209 - x` ／ `Z = z - 71.91`）で変換したものです。

### ★ 高さの問題（ここが本題）

**presence には高さ(Y)がありません。** `x`/`z`/`向き` だけです。

そのため、**そちらがいまの実装のままだと、ステージに上がった人は
「ステージの中に埋まる」か「宙に浮く」**ことになります。
clubVERSE のステージ天面は**床から約1.4m**上がっているためです。

**お願い**: **その座標の「床の高さ」に合わせてプロキシを置いてください。**
真下にレイを飛ばして床を拾う、で構いません。
そちらのワールドの床の高さは、そちらが正確に知っている情報なので、
**こちらから高さを送るより、そちらで解決してもらう方が確実**だと考えました。

⚠ **presence に高さを足す案（v=2）も採れます。** そちらの作りによっては
そのほうが早いかもしれません。**判断はそちらに任せます。要るなら言ってください。**

### そちらが何もしなかった場合

**登壇した人（管理人・VIPのみ）が、ステージの中に埋まって見えます。**
客席のお客さんには影響しません。壊れはしませんが、見た目は良くありません。

  従来どおり客席の床の高さ固定に戻せます（そちらの作業は不要）
