## 1. いちばん大事な設計判断: ポイントはサーバーが持つ

**残高・所持品・抽選の結果は、すべてサーバーで決めてサーバーに保存する。**
クライアントは「いくら持っているか」を表示するだけにする。

理由: ブラウザの値は誰でも書き換えられる。スロットの当たりをクライアントで決めると、
通信を差し替えるだけで無限に増やせる。**お金の匂いがするものは1か所（サーバー）でしか動かさない。**

保存先はいまと同じ **Turso**（無料枠）。テーブルは3つで足りる:

| テーブル | 中身 |
|---|---|
| `wallets` | メールアドレス（=アカウント）と残高 |
| `ledger` | 増減の履歴（いつ・いくら・理由・関連id）。**残高はこの合計と必ず一致させる** |
| `inventory` | 誰が何をいくつ持っているか |

⚠ 残高を直接書き換えず、**必ず履歴を書いてから残高を更新する**。
そうしないと「増えた理由が分からない残高」が生まれ、不正か不具合か判断できなくなる。

⚠ **ゲスト（未ログイン）はポイントを持てない。** ブラウザを消せば別人になるので、
残高を持たせると無限に作り直せてしまう。

## 3. 使いみち

- **お店**: アバターの飾り（アクセサリー・色・運営専用でないもの）やエモートを買う → `inventory` に入る
- **インベントリー**: 買ったものの一覧。着せ替え画面から選べるようになる
- **ガチャ**: 抽選。**確率をサーバーに持ち、履歴に残す**
- **カジノ**: スロット、ポーカー

## 4. カジノについて（先に決めておきたいこと）

**無料でしか手に入らないポイントで遊び、換金も現物交換もしない**なら、
いわゆる賭博には当たらない（ソーシャルゲームのミニゲームと同じ扱い）。
ただし**次のどれかをやると意味が変わる**ので、そのときは必ず相談してから:

- ポイントを**現金で買えるようにする**（今回は入れない）
- ポイントを**現金・商品券・物品に換える**
- ポイントを**ユーザー同士でやり取りできるようにする**（換金の抜け道になる）

また、確率と期待値は**画面に出す**（ガチャの確率表示）。後で揉めないため。

## 5. 場所（建物の中に作る）

loyさん「建物内でお店やカジノ店など作りたい」。

いまの街（CITY）は**タイル状に自動生成した仮の建物**が並んでいる。
店やカジノは「入れる建物」なので、自動生成とは別に**決まった場所に手で置く**。

- 街の中に**入れる建物**を数棟決め、扉の前に立つと中に入れる
- 中は**別の小さな部屋**として作る（会場やCITYと同じ仕組みの、狭いワールド）
- 中でしか使えないUI（お店の棚、スロット台、ポーカー卓）を置く

⚠ 部屋を増やすと**通信の相手も増える**。負荷テストの結論（1ルームの人数で決まる）から、
店やカジノの部屋は**定員を小さく**（10人程度）しておくのが安全。

## 6. 作る順番（案）

1. **土台**: 残高・履歴・付与（ログインボーナスだけ）＋画面の残高表示
2. **お店とインベントリー**: 買う → 持ち物に入る → 着せ替えで使える
3. **建物に入れるようにする**（街に扉を置き、中の部屋を作る）
4. **ガチャ**（確率表示つき）
5. **カジノ**（まずスロット。ポーカーは人と対戦するので最後）

各段階で動くものになるので、途中で止めても無駄になりません。

## 7. 後回しにするが忘れないこと

- 現金購入（決済・返金・税・利用規約）
- ユーザー間のやり取り（換金の抜け道になるので入れるなら慎重に）
- 不正対策の作り込み（自動操作で貯める／同一人物の複数アカウント）
- VRChat側との共有（向こうにも残高を出すか。出すなら presence の契約に足す）
