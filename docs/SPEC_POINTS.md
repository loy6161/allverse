## 1. いちばん大事な制約

**VRChatのワールドは、外部へ書き込めない。** 読むのは `VRCStringDownloader`（5秒に1回）でできるが、
書くのは**Udonがログに出す → loyさんのPCで harvester が拾って送る**という迂回しかない。

つまり「同じ残高を両方から増減する」を素直に作ると、**VRC側の消費だけが遅れて届く**（しかも
loyさんのPCが起動していないと届かない）。ここをどう扱うかが設計の芯になります。

## 2. 提案: 台帳は ALLVERSE Worker 1つ。ブラウザは残高を持たない

```
                    ┌──────────── ALLVERSE Worker（台帳＝唯一の正）────────────┐
ブラウザ会場 ──即時─▶│  残高 / 履歴 / インベントリ（itemId）                     │
（HTTPSで直接）      │                                                          │
VRCワールド ──読む──▶│  live.json に残高を同梱（5秒ポーリングの既存の枠に相乗り） │
   └─消費─▶ ログ ─▶ harvester ─▶ POST ─────────────────────────────────────────┘
```

- **ブラウザ側サーバー（Render）は残高を持たない。** 二重に持つと必ずズレ、どちらが正か分からなくなる
- ブラウザでの購入・当選は**その場でWorkerへ問い合わせて確定**（即時・確実）
- VRC内の消費は**既存の harvester の道**に相乗りする（新しい仕組みを作らない）
- VRC内の表示は PlayerData を**キャッシュ**として使い、入室時に台帳の値で上書きする（外が正）

⚠ この形の弱点: **harvester が動いていない間、VRC内の消費は台帳に届かない。**
「VRCで使った → ブラウザを開いたらまだ減っていない」が起きます。許容するか、
VRC内の消費を harvester 稼働中だけに限るか、決めておく必要があります。

## 3. アイテムの共通化

**`itemId`（2バイトの通し番号）を両世界で共有する。** VRC側は既に
「並べ替え禁止・追加は末尾のみ・0は欠番」という規則を決めているので、**そのまま共通の台帳にできます**。

- **IDだけが共通。見た目は各世界が自前で用意**（ブラウザ=GLB／VRC=prefab）
- ブラウザに実体が無いアイテム（家具など）は、ブラウザでは**持っているが飾れない**扱いにする
- カタログ（名前・価格・アイコン・カテゴリ）は**Workerに置いて両方が読む**のが理想。
  VRC側はいまワールド内の並列配列に持つ設計なので、**ここは相談が要る**

## 4. ブラウザ側で作るもの（台帳を持たない前提）

1. **残高の表示**（画面上部）と、Workerからの取得
2. **お店**: 一覧 → 買う（Workerが確定）→ インベントリに入る
3. **インベントリ**: 持ち物一覧。着せ替え画面から使える
4. **ガチャ**: 抽選は**Workerが引く**（確率表示つき）
5. **カジノ**: スロット → ポーカー。**当たり外れはサーバーが決める**（ブラウザで決めると書き換えられる）
6. **建物の中**: 街に入れる建物を数棟置き、中を小さな部屋として作る（定員は10人程度）
