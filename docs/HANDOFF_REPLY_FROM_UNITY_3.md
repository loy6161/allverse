## 返事（§6の4項目）

### 1. この素材でプロキシアバターを組むか → ✅ 受領・この素材で組みます（新規制作しない）

- 11ファイルすべてローカルで確認済み（`assets\avatars\`・合計185KB）
- GLB内のマテリアル名を検証し、仕様どおりであることを確認:
  - body系: `MatSkin` `MatCloth` `MatDark` `MatEyeC` `MatEye` `MatEyeGlint` `MatCheek`
  - hair系・acc系: `MatHair`
  - 可動ノード `armL/armR/legL/legR` も確認
- 塗り分けは「マテリアル名 → `av` の色番号 → 14色/8色表のHEX」で実装する。`MatDark`（脚）は
  提案どおり固定暗色 `#2a2028` で入れる（髪色からの生成はしない）。シェーダーはlilToon系でトゥーン寄せ
- **範囲外id/番号は index 0 にフォールバック**する実装にする（そちらと同じ挙動。パーツ追加で壊れない）

### 2. スケール → **一旦「等倍 1.16m」で実装。βテスト後に再調整**（loyさん判断 2026-07-30）

- loyさんの意図: VRCアバターは日本だと140cm前後が主流だが、それに合わせると**通常のVRCユーザーが
  ライブを見づらくなる恐れ**がある。ブラウザ勢はVRC側の目線を持たない（見え方に関係しない）ので、
  **少し小さめの方がむしろ良い**。まず等倍で出し、βで見てから調整する
- こちらの実装対応: **スケール値をインスペクタ変数で外出し**し、後からβの様子で1つの数値を変えるだけで
  全プロキシに反映できるようにする（再ビルド不要の運用を目指す）

### 3. 向き・前後・上下の確認 → 取り込み時に必ずやる（§2のX+90°回転を把握済み）

- 各ノードがX軸+90°回転を持つ件、Unityインポータでの解決を前提にしつつ、**取り込み直後に
  横倒し/前後逆が出ていないか目視確認**する。出たらこの回転の扱いで対処する
- なお presence の `r`（向き）は左右反転リスクが座標変換由来で残っているので（返答②参照）、
  **アバターの前方向とpresence.rの向きが一致するかは、ブラウザ側との合同テストで最優先確認**する

### 4. 足りない情報 → 下記だけ確認したい（急ぎではない）

- **エモート**: presence.jsonに状態が載っていない件、把握。当面は歩行/待機だけで作り、
  手ふり・拍手・ペンライト等の同期が欲しくなったら `v=2` で相談させてほしい（loyさん方針：位置が先）
- **ペンライト色 `av.pl`**: 14色表で受け取るが、ペンライトのメッシュは素材に含まれていない認識。
  こちら側で用意する（観客演出のペンラと共用）。それで問題ないか一応確認したい
- **瞳 `av.ec`**: `MatEyeC` に14色表で反映、`MatEye`/`MatEyeGlint`/`MatCheek` は固定色、で認識合ってるか

## 補足：こちら側の方針（共有）

- **この素材を YouTube観客NPC にも流用**する予定。もともとYouTube視聴者用のNPCを別途作る計画だったが、
  同じ素材で「ブラウザ勢もYouTube勢も同じ見た目システム」に一本化できるため。配布可の素材なので問題ない認識
- 旧 `PRESENCE_SPEC.md` 付録A（髪4種・8色）は破棄し、本文書（髪6種・14色・服3種・アクセ2種＝54通り）を
  正本として設計書に反映済み
- スケール以外の見た目仕様は本文書に従う。変更時は `v` を上げて事前相談、で認識一致
