## 1. 全体像（あなたのギミックがどこに位置するか)

```
【ブラウザ版 VERSE CITY Web】                【VRChat版 VERSE CITY】
 ブラウザ勢が歩き回る                          あなたが開発中のワールド
      │                                            ▲
      ▼                                            │
 同期サーバー（Node.js・稼働中）                     │ 5秒ごとに取得して
      │                                            │ 客席にアバター表示
      └──▶ GET /api/presence.json ────────────────┘
           「今ブラウザ側に誰がどこにいるか」のJSON
           （将来はYouTubeコメント勢のリストもここに統合するかも＝§5）
```

- ブラウザ勢の位置・名前・アバターの見た目は、サーバーが `presence.json` というURLで常時公開している
- VRC側はそれを**約5秒ごとに取得**（VRCStringDownloaderの制限）して、客席にプロキシアバターを出す
- 逆方向（VRC勢をブラウザに出す）も構想はあるが**今回はやらない**（§2の3で「仕込み」だけ任意依頼）

## 2. お願いしたいこと（優先順）

1. **presence.json を読んで、ブラウザ勢を客席に出現・移動させるギミック**
   - 既存のYouTubeコメント勢ギミックの「取得先URLとデータ形式を差し替えた版」のイメージ
   - **インスタンスマスターだけが取得**し、同期変数で全クライアントへ配布する方式を推奨
   - 座標反映はワープではなく、次回更新までの約5秒で歩かせる補間を推奨
   - `ts`（サーバー時刻）が60秒以上古ければサーバー停止とみなし退場処理
2. **プロキシアバターの見た目**: ブラウザ側でユーザーがカスタムした見た目を再現する（合意済み方針）
   - 髪型4種（short/long/twin/hat）のメッシュ＋肌8色・髪8色・服8色のティントを用意すれば再現できる
   - **色とidの対応表は同フォルダ PRESENCE_SPEC.md の付録Aが正**（両世界の共通契約。勝手に変えない）
3. **（任意・仕込みだけ）将来の逆方向連携用のログ出力**: ワールド内の全プレイヤー座標を
   `[VCITY1]{"p":[["VRCユーザー名",x,z,r],...]}` 形式で毎秒 Debug.Log する仕組み（スタッフ用スイッチで既定OFF）
   - 外部の中間ソフトがログを拾ってサーバーに送る計画（PRESENCE_SPEC.md §3）。やるかは未定なので後回しでOK

## 3. presence.json の形式（実際にサーバーが返した実物）

```json
{
  "v": 1,
  "ts": 1783990281,
  "web": [
    { "rm": 1, "n": "loy", "x": 0, "z": 18, "r": 0,
      "av": { "h": "long", "hc": 2, "sc": 2, "bc": 4 } },
    { "rm": 1, "n": "ゲストB", "x": -5.9, "z": 12.1, "r": -135,
      "av": { "h": "long", "hc": 4, "sc": 0, "bc": 7 } }
  ],
  "yt": []
}
```

| フィールド | 意味 |
|---|---|
| `ts` | サーバー時刻（UNIX秒）。鮮度チェック用 |
| `web[]` | ブラウザ勢。インスタンス番号（`rm`）昇順で整列済み |
| `n` / `x` / `z` / `r` | 表示名／座標（m・小数1桁）／向き（度） |
| `av` | アバター見た目。`h`=髪型id、`hc`/`sc`/`bc`=髪色/服色/肌色の番号（付録A参照） |
| `yt[]` | 現在は常に空（§5参照） |

- **表示上限はVRC側で決めてよい**。上限まで配列の先頭から採用すれば「#1のインスタンスから順に表示」になる（合意済み仕様）
- 座標系: 「メインステージ中心の床が原点、ステージ正面方向が -Z、単位メートル」。VRC側ワールドとのズレはUdon側の定数オフセット・回転で吸収する想定

## 4. 開発の進め方（推奨2段階）

1. **開発中**: Unityエディタで普通のC#（UnityWebRequest）から `http://localhost:5179/api/presence.json` を5秒ポーリングして動きを作り込む（VRChat制約なしで作業できる）
   - ローカルサーバーの起動: `cd L:\企画用\WEB\verse_city_web\server && npm install`（初回のみ）→ `npm start`
   - ブラウザで http://localhost:5179 を開いて入場すれば、テスト用の「ブラウザ勢」を自分で作れる
2. **本番**: 取得部分だけ VRCStringDownloader + VRCJson に差し替え。URLは公開後のRender URL（https）を VRCUrl として設定（公開されたら共有される）

## 5. 決まっていること・未定のこと

**合意済み（変えたい場合はブラウザ側チャットと要調整）**
- 承認設計: ブラウザ入場＝VRC側に表示されることへの同意（規約に明記予定）
- 優先順位: ①ブラウザ勢→VRC表示（今回の依頼）、②VRC勢→ブラウザ表示（仕込みのみ・実施未定）
- YouTube関連では「ワールド内チャット→YouTubeチャットへのクロスポスト」を優先開発する（別途、ポータルのGoogle認証とセットで設計予定）

**未定（Unity側の裁量でOK、決めたら共有）**
- プロキシアバターの具体デザイン（既存コメント勢アバターの改修 or 新規制作）
- 既存ギミックのYouTubeコメント取得を将来この `yt[]` に一本化するか（利点: API枠節約・リスト一致。急がない）
- ブラウザ勢のチャット文言もVRC側に表示するか（サーバー側に `web[].c` フィールドを用意済み・既定OFF。欲しくなったら連絡）
