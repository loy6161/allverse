- ブラウザ版メタバースのフェーズ①（プリセットアバター・歩き回り・チャット・リアルタイム同期）は**ローカル実装済み・動作検証済み**

  - 起動: `cd L:\企画用\WEB\verse_city_web\server && npm start` → http://localhost:5179
  - これ1本で「クライアント配信＋WebSocket同期＋VRC連携API」を提供
- **VRC連携API（Unity側が読む対象）は稼働中**:
  - `GET http://localhost:5179/api/presence.json` … ブラウザ側にいる人の一覧（形式は下記§3）
  - `GET http://localhost:5179/api/status` … ルーム状況
- デプロイ（Render無料プラン）は準備完了・ユーザーのGitHub push待ち。公開後は
  `https://<render発行URL>/api/presence.json` に差し替わる（形式は同一）

## 2. Unity側にお願いしたいこと（優先順）

1. **presence.json を読んで、ブラウザ勢を客席にプロキシアバターとして出現・移動させるギミック**
   - 既存の「YouTubeコメント勢を出現させるギミック」の取得先とデータ形式を差し替えるイメージ
   - 取得間隔: 約5秒（VRCStringDownloaderの制限に合わせる）
   - **インスタンスマスターだけが取得**し、同期変数で全クライアントへ配布する方式を推奨
   - 座標反映はワープではなく、次回更新までの約5秒で歩かせる補間を推奨
   - `ts`（サーバー時刻）が60秒以上古ければサーバー停止とみなし退場処理
2. **プロキシアバターの見た目**: ブラウザ側のカスタムを再現する方針で確定済み
   - 髪型4種（short/long/twin/hat）のメッシュ＋肌8色・髪8色・服8色のティント
   - **色とidの対応表は PRESENCE_SPEC.md 付録Aが正**（両世界の共通契約。勝手に変えない）
3. **（実装だけ仕込んでおく・任意）方向②用のログ出力**: ワールド内の全プレイヤー座標を
   `[VCITY1]{"p":[["VRCユーザー名",x,z,r],...]}` 形式で毎秒 Debug.Log する仕組み
   - スタッフ用スイッチで ON/OFF（既定OFF）。詳細は PRESENCE_SPEC.md §3.1
   - これがあると将来「VRC勢をブラウザ側に表示」がすぐ実現できる（やるかは未定のまま）

## 3. presence.json の形式（実物サンプル）

```json
{
  "v": 1,
  "ts": 1783990281,
  "web": [
    { "rm": 1, "n": "loy", "x": 0, "z": 18, "r": 0,
      "av": { "h": "long", "hc": 2, "sc": 2, "bc": 4 } },
    { "rm": 1, "n": "ゲストB", "x": -5.9, "z": 12.1, "r": -135,
      "av": { "h": "long", "hc": 4, "sc": 0, "bc": 7 } }
  ],
  "yt": []
}
```

- `web[]` はインスタンス番号（`rm`）昇順で整列済み。**VRC側で決めた表示上限まで先頭から採用**すれば「#1から順にインスタンスまたぎで表示」になる（確定済みの仕様）
- `x`/`z` はメートル・小数1桁、`r` は向き（度）。座標系は「ステージ中心の床が原点、ステージ正面方向が -Z」（PRESENCE_SPEC.md §2.3。VRC側ワールドとのズレはUdon側の定数オフセットで吸収）
- `yt[]` は現在常に空。YouTubeコメント勢の一本化は将来の相談事項（急がない）

## 4. 開発の進め方（推奨2段階）

1. **開発中**: Unityエディタで普通のC#（UnityWebRequest）から `http://localhost:5179/api/presence.json` を5秒ポーリングして動きを作り込む（VRChat制約なしで作業できる）
   - ローカルサーバーはブラウザ側チャットの環境で起動している前提。自分で起動する場合は§1のコマンド
2. **本番**: 取得部分だけ VRCStringDownloader + VRCJson に差し替え。URLはRenderの公開URL（https）を VRCUrl として設定

## 5. 決まっていること・決まっていないこと

**確定（変えるときはブラウザ側チャットと要調整）**
- 承認設計: ブラウザ入場＝VRC側表示への同意（規約明記）／VRC勢のブラウザ表示はポータルでのVRCユーザー名登録者のみ
- 優先順位: ①ブラウザ&YouTube→VRC（今回の依頼）、②VRC→ブラウザ（仕込みのみ）
- YouTube連携は「ワールド内チャット→YouTubeチャットへのクロスポスト」を取り込みより優先（ポータルのGoogle認証とセットで後日設計）

**未定（Unity側の裁量でOK、決めたら一言共有）**
- プロキシアバターの具体デザイン（既存コメント勢アバターの改修 or 新規）
- yt[] 一本化への移行タイミング
- ブラウザ勢のチャット文言表示（`web[].c` フィールドは機能フラグで用意済み・既定OFF。欲しくなったら連絡）
