# VERSE CITY Web リアルタイム同期プロトコル v1

クライアント（ブラウザ）とサーバー間のWebSocket通信仕様。サーバー班・ネット班の共通契約。

- WS接続先: `ws://<host>:5179/ws`
- メッセージは全てJSONテキスト1件ずつ
- 座標: ワールド座標（メートル、小数1桁で量子化）。`r`=向き（度、整数）。原点等は PRESENCE_SPEC.md §2.3 に従う
- `av` はプリセット番号形式（PRESENCE_SPEC.md 付録Aと同一）: `{ h: "twin", hc: 5, sc: 0, bc: 1 }`

## クライアント → サーバー

| 種別 | 形式 | 備考 |
|---|---|---|
| 入場 | `{"t":"join","n":"loy","av":{"h":"twin","hc":5,"sc":0,"bc":1}}` | 接続後最初に1回。nは1〜12文字（サーバーでも強制トリム） |
| 位置 | `{"t":"pos","x":3.2,"z":-12.5,"r":90,"m":true}` | 最大10Hz。`m`=移動中フラグ |
| チャット | `{"t":"chat","txt":"こんにちは"}` | txtは最大200文字（サーバーでも強制トリム） |
| 変更 | `{"t":"update","n":"loy","av":{...}}` | アバター再カスタム時 |
| エモート | `{"t":"emote","e":"wave"}` | e は既定リストのidのみ（後述）。連打防止のため毎秒2回まで |
| スクリーン | `{"t":"screen","v":"unrobrGhlv0"}` | YouTube動画IDのみ（11文字 `[A-Za-z0-9_-]`）。ルーム全体の共有状態を変更する |
| 再生操作 | `{"t":"playback","st":"play","pos":123.4}` | 再生/一時停止/シーク。`st`は`play`か`pause`、`pos`は再生位置(秒)。ルーム全員の再生位置を揃える |

## サーバー → クライアント

| 種別 | 形式 | 備考 |
|---|---|---|
| 入場応答 | `{"t":"welcome","id":"c12","room":1,"peers":[...],"count":5,"screen":"unrobrGhlv0"}` | joinへの応答。peersは同室の既存メンバー全員。countは自分含む同室人数。screenは現在ルームで再生中の動画ID（途中入場者もすぐ追従できる） |
| 参加通知 | `{"t":"peer-join","p":{"id":"c3","n":"...","av":{...},"x":0,"z":18,"r":0}}` | |
| 位置 | `{"t":"pos","id":"c3","x":3.2,"z":-12.5,"r":90,"m":true}` | 発信者以外の同室全員へ中継 |
| 変更通知 | `{"t":"peer-update","id":"c3","n":"...","av":{...}}` | |
| 退出通知 | `{"t":"peer-leave","id":"c3"}` | |
| チャット | `{"t":"chat","id":"c3","n":"...","txt":"..."}` | 同室全員へ（発信者自身にも返す。クライアントは id==自分 なら無視してよい） |
| 人数 | `{"t":"count","c":8}` | 同室人数が変わったとき |
| エモート | `{"t":"emote","id":"c3","e":"wave"}` | 発信者以外の同室全員へ中継（自分の分はローカルで即再生） |
| スクリーン | `{"t":"screen","v":"unrobrGhlv0","by":"loy"}` | 同室全員へ（発信者含む）。`by`=変更した人の表示名（チャットに「○○がスクリーンを変更しました」と出す用） |
| 再生操作 | `{"t":"playback","id":"c3","st":"play","pos":123.4}` | 発信者以外の同室全員へ中継。受信側は自分の映像をこの位置・状態に合わせる |

### 再生状態の共有について

- サーバーはルームごとに `{ playing, pos, at }` を保持し、`pos` は最後の更新時点の再生位置、`at` はその時刻
- 現在位置は `playing ? pos + (now - at) : pos` で求める。途中入場者の `welcome` にはこの計算結果が入る
- 動画を差し替えると再生状態は先頭・再生中にリセットされる
- **音量とミュートは共有しない**（各自の手元の設定）

## エモート一覧（クライアント・サーバー共通の固定リスト）

| id | 表示 | 動作 |
|---|---|---|
| `wave` | 👋 手をふる | 片手を上げて左右に振る |
| `clap` | 👏 拍手 | 両手を胸の前で叩く |
| `jump` | ⤴️ ジャンプ | その場で数回跳ねる |
| `dance` | 🕺 おどる | 体を左右に揺らす＋腕を振る（ループ長め） |
| `heart` | 💗 ハート | 両手を頭上で合わせてハートを作る |
| `penlight` | 🔦 ペンライト | 発光する棒を持って振る（ライブ会場用） |

- サーバーはこのリストにないidを破棄する
- 各エモートは2〜4秒で自動的に待機に戻る（移動を始めても中断して歩行に戻る）

## ルーム制

- 1ルーム定員 `MAX_PER_ROOM = 30`
- 新規接続は「空きのある最小番号ルーム」に割り当て（#1→#2→…）
- 中継（pos/chat等）はすべて同室内のみ

## HTTPエンドポイント（同じサーバーが提供）

| パス | 内容 |
|---|---|
| `GET /` | ステータスJSON `{ok:true, rooms:[{room:1,count:8}], uptime:秒}` |
| `GET /api/presence.json` | PRESENCE_SPEC.md §2.2 の形式（全ルーム、#1から昇順、最大60人、CORS: *）。`yt[]` は現段階では常に空配列 |

## サーバー側の防御（最低限）

- join前の他メッセージは無視
- 1クライアント毎秒20メッセージ超は破棄
- 不正JSON・想定外の `t` は無視（切断まではしない）
- 切断時は peer-leave / count を同室へ通知
