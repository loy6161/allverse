# VERSE CITY Web リアルタイム同期プロトコル v1

クライアント（ブラウザ）とサーバー間のWebSocket通信仕様。サーバー班・ネット班の共通契約。

- WS接続先: `ws://<host>:5179/ws`
- メッセージは全てJSONテキスト1件ずつ
- 座標: ワールド座標（メートル、小数1桁で量子化）。`r`=向き（度、整数）。原点等は PRESENCE_SPEC.md §2.3 に従う
- `av` はプリセット番号形式（PRESENCE_SPEC.md 付録Aと同一）: `{ h:"twin", o:"middle", ac:"none", hc:5, sc:0, bc:1, ec:1 }`

## 場所の構造（2026-07-29〜）

**イベント ＞ ルーム** の二層。イベントが動画と再生位置の持ち主で、同じイベントなら
**全ルームが同じ動画・同じ再生位置**になる。ルームはイベント内の分割（定員30人）。

中継の届く範囲は権限で変わる。
- 一般（user/guest）… 自室のみ
- 管理者・VIP（admin/vip）… **同じイベントの全ルーム**（姿・チャット・エモート）

## クライアント → サーバー

| 種別 | 形式 | 備考 |
|---|---|---|
| 入場 | `{"t":"join","n":"loy","av":{...},"idt":"<GoogleのIDトークン>","ev":"main","rm":1}` | 接続後最初に1回。nは1〜12文字。`idt`/`ev`/`rm`は任意（`idt`があれば権限判定、無ければゲスト） |
| 位置 | `{"t":"pos","x":3.2,"z":-12.5,"r":90,"m":true}` | 最大10Hz。`m`=移動中フラグ |
| チャット | `{"t":"chat","txt":"こんにちは","sc":"local"}` | txtは最大200文字。`sc`は`local`(既定)か`stream`。`stream`は管理者のみ |
| 変更 | `{"t":"update","n":"loy","av":{...}}` | アバター再カスタム時。ゲストは拒否される |
| エモート | `{"t":"emote","e":"wave"}` | e は既定リストのidのみ（後述）。連打防止のため毎秒2回まで。ゲストは拒否される |
| スクリーン | `{"t":"screen","v":"unrobrGhlv0"}` | YouTube動画IDのみ（11文字 `[A-Za-z0-9_-]`）。**管理者のみ**。イベント全体の共有状態を変更する |
| 再生操作 | `{"t":"playback","st":"play","pos":123.4}` | 再生/一時停止/シーク。**管理者のみ**。イベント全員の再生位置を揃える |
| 移動 | `{"t":"move","ev":"main","rm":2}` | 別のイベント/ルームへ移動。`rm`省略時は空いている部屋へ自動割当 |
| イベント作成 | `{"t":"event-create","name":"WEEKENDS vol.12","v":"...","requireLogin":false}` | **管理者のみ**。上限20件 |
| イベント削除 | `{"t":"event-delete","id":"ev..."}` | **管理者のみ**。常設イベントと、人が残っているイベントは削除できない |
| 一覧要求 | `{"t":"events"}` | イベント／ルーム一覧を返してもらう |

## サーバー → クライアント

| 種別 | 形式 | 備考 |
|---|---|---|
| 入場応答 | `{"t":"welcome","id":"c12","role":"user","canControl":false,"ev":"main","event":{...},"room":1,"peers":[...],"count":5,"screen":"...","playback":{...},"events":[...],"persistent":true}` | joinへの応答。`role`は`admin`/`vip`/`user`/`guest`。**`canControl`が動画操作の可否の唯一の正**（クライアントは自分で判定しない） |
| 参加通知 | `{"t":"peer-join","p":{"id":"c3","n":"...","av":{...},"x":0,"z":18,"r":0,"role":"vip"}}` | |
| 位置 | `{"t":"pos","id":"c3","x":3.2,"z":-12.5,"r":90,"m":true}` | 発信者以外へ中継（範囲は上記「場所の構造」参照） |
| 変更通知 | `{"t":"peer-update","id":"c3","n":"...","av":{...}}` | |
| 退出通知 | `{"t":"peer-leave","id":"c3"}` | |
| チャット | `{"t":"chat","id":"c3","n":"...","txt":"...","sc":"local"}` | 発信者自身にも返す（クライアントは id==自分 なら無視してよい） |
| 人数 | `{"t":"count","c":8}` | 同室人数が変わったとき |
| エモート | `{"t":"emote","id":"c3","e":"wave"}` | 発信者以外へ中継（自分の分はローカルで即再生） |
| スクリーン | `{"t":"screen","v":"unrobrGhlv0","by":"loy"}` | **イベントの全ルーム**へ（発信者含む）。`by`=変更した人の表示名 |
| 再生操作 | `{"t":"playback","id":"c3","st":"play","pos":123.4}` | 発信者以外の**イベント全ルーム**へ中継 |
| 移動完了 | `{"t":"moved","ev":"...","event":{...},"room":2,"peers":[...],"count":3,"screen":"...","playback":{...}}` | moveへの応答。受信側は周りの人を総入れ替えする |
| イベント一覧 | `{"t":"events","events":[{"id","name","v","count","requireLogin","permanent","rooms":[{"room","count","full"}]}]}` | 人数やイベントが変わったとき／要求時 |
| 作成応答 | `{"t":"event-created","ev":{...}}` | event-create の成功時（作成者のみ） |
| 拒否 | `{"t":"denied","reason":"admin-only"}` | 権限不足など。reasonは `admin-only` / `guest-no-chat` / `guest-no-emote` / `guest-no-avatar` / `login-required` / `event-not-empty` / `cannot-delete` / `too-many-events` |

### 再生状態の共有について

- サーバーは**イベントごと**に `{ playing, pos, at }` を保持し、`pos` は最後の更新時点の再生位置、`at` はその時刻
- 現在位置は `playing ? pos + (now - at) : pos` で求める。途中入場者の `welcome` にはこの計算結果が入る
- 動画を差し替えると再生状態は先頭・再生中にリセットされる
- **音量とミュートは共有しない**（各自の手元の設定）

### 権限について

- `idt` は Google Identity Services のIDトークン。サーバーが Google の公開鍵で検証し、メールアドレスを取り出す
- 権限は `ADMIN_EMAILS` / `VIP_EMAILS`（環境変数）との突き合わせで決まる
- **`GOOGLE_CLIENT_ID` 未設定の間は全員 `user` 扱いで、動画操作も誰でもできる**（ログイン手段が無いのに締め出さないための移行措置）
- 設定手順は SETUP_AUTH.md

## エモート一覧（クライアント・サーバー共通の固定リスト）

| id | 表示 | 動作 |
|---|---|---|
| `wave` | 👋 手をふる | 片手を上げて左右に振る |
| `clap` | 👏 拍手 | 両手を胸の前で叩く |
| `jump` | ⤴️ ジャンプ | その場で数回跳ねる |
| `dance` | 🕺 おどる | 体を左右に揺らす＋腕を振る（ループ長め） |
| `heart` | 💗 ハート | 両手を頭上で合わせてハートを作る |
| `penlight` | 🔦 ペンライト | 発光する棒を持って振る（ライブ会場用） |

- サーバーはこのリストにないidを破棄する
- 各エモートは2〜4秒で自動的に待機に戻る（移動を始めても中断して歩行に戻る）

## ルーム制

- 1ルーム定員 `MAX_PER_ROOM = 30`
- ルームキーは `<eventId>#<番号>`。ルーム番号はイベントごとに1から振り直される
- 入場・移動でルーム番号を指定できる。指定が無い/満室なら「空きのある最小番号ルーム」へ（#1→#2→…）
- 中継は同室内のみ。ただし **admin/vip は同じイベントの全ルーム**へ届く
- 常設イベント `main` は必ず存在し削除できない

## HTTPエンドポイント（同じサーバーが提供）

| パス | 内容 |
|---|---|
| `GET /api/status` | ステータスJSON `{ok, rooms:[{event,room,count}], events:[...], persistent, login, uptime}` |
| `GET /api/config` | 入場画面用 `{ok, login, clientId, persistent, events:[...]}`。`clientId`はGoogleのOAuthクライアントID（公開情報） |
| `GET /api/presence.json` | PRESENCE_SPEC.md §2.2 の形式（最大60人、CORS: *）。`yt[]` は現段階では常に空配列 |

### presence.json とイベントの関係（重要）

`rm` はルーム番号なので、イベントをまたぐと番号が衝突し「別のイベントにいる人が同じ部屋にいる」ように見えてしまう。
**v=1 は凍結**なのでフィールドを増やさず、VRC側へ出すのは**常設イベント(main)のみ**に限定している。
特別イベントの参加者も流したくなった場合は、Unity側と v=2 の相談が必要。

## サーバー側の防御（最低限）

- join前の他メッセージは無視
- 1クライアント毎秒20メッセージ超は破棄
- 不正JSON・想定外の `t` は無視（切断まではしない）
- 切断時は peer-leave / count を同室へ通知
