## 1. 確認2点への回答

### ペンライト `av.pl` → **そちらで用意してもらってOKです**

認識のとおり、**ペンライトのメッシュは配布した素材に含まれていません**。
ブラウザ側では実行時にコード（円柱＋発光板）で組み立てていて、GLBには入っていないためです。
観客演出のペンラと共用していただいて問題ありません。

参考までに、ブラウザ側での見え方はこうです（合わせたい場合の目安。厳密一致は不要）。

| 部位 | 内容 |
|---|---|
| グリップ | 直径 約0.038m × 長さ0.07m・色 `#2a2a34` |
| 発光部 | 直径 約0.044m × 長さ0.19m。色は下記 |
| 光の広がり | 加算合成の板を十字に2枚（不透明度0.33） |
| 持ち手 | 右手（`armR`）の子。ペンライトのエモート中だけ表示 |

**発光部の色**: `av.pl` の14色をそのまま使うのではなく、**白に30%寄せて明るく**しています。

```
発光色 = lerp(14色表[av.pl], #ffffff, 0.3)
```

そのまま14色を使うと暗い色（黒 `#1a1a1a` など）を選んだ人のペンライトが光って見えないためです。
そちらでも同じ処理を入れるか、あるいは発光マテリアルの明度で担保していただければ大丈夫です。

### 瞳 `av.ec` → **認識どおりで合っています**（1点だけ補足）

| マテリアル | 色 |
|---|---|
| `MatEyeC`（瞳） | **`av.ec` の14色をそのまま** |
| `MatEye` | 固定 `#191219` |
| `MatEyeGlint` | 固定 `#ffffff`（陰影なし・発光扱い） |
| `MatCheek` | 固定 `#ff96a0` |

**補足**: ブラウザ側には「`av.ec` が無い場合は髪色から導出する」というフォールバックがありますが、
これは**古いクライアント向けの互換処理**で、いまのクライアントは必ず `av.ec` を送ります。
presence.json 経由で届く `av` にも常に `ec` が入るので、**そちらは常に14色表を引くだけで大丈夫です**。

## 2. ★ イベントの運用が変わりました（VRChat連携に影響します）

**presence.json の中身が空になる条件が増えました。** 実装変更は不要だと思いますが、
「出ないときの原因」を知っておいてもらうために共有します。

### 何が変わったか

これまで `main` という**常設イベントが必ず存在**し、ブラウザ勢は常にそこに入っていました。
2026-07-30、これを**廃止**しました（loyさん判断）。理由は、URLを知っていれば
調整中でも誰でも入れてしまい、管理人が会場を閉じる手段が無かったためです。

いまは **管理人がイベントを立てている間だけ会場が開きます**。
パブリックで立てて閉じなければ、結果としてそれが常設になります。

### presence.json に人が出る条件

```
① 管理人がイベントを立てている
② そのイベントの「VRChatに出す」設定がONになっている  ← 新設
③ そのイベントに人が入っている
```

**②が新設です。** VRChat側の会場は clubVERSE 1つなので、ブラウザ側に複数のイベントが
あるとき「どれをVRCに映すか」を決める必要がありました。**同時にONにできるのは1つだけ**で、
別のイベントをONにすると自動で前のイベントはOFFになります。

したがって、`web[]` が空でも異常とは限りません。次のどれかです。

| `web[]` が空になる理由 | 状況 |
|---|---|
| 会場が閉まっている | 管理人が何も立てていない（調整中など） |
| 連携がOFF | イベントはあるが「VRChatに出す」がOFF |
| 単に誰もいない | 従来どおり |

`ts` は常に更新されるので、**「サーバーが生きているのに `web[]` が空」は正常な状態**として
扱ってください（既にそう実装されていると認識しています）。

### そちらの実装変更は不要のはずです

- スキーマ `v=1` は変えていません。`web[]` の中身も座標系も申し送り②のままです
- 「presenceが空＝誰もいない」を既に正しく扱っていると返答②でいただいているので、
  そのままで動くはずです

### ついでに: イベントごとの設定

管理人が立てるときに選べるようになりました（あとから変更もできます）。

| 設定 | 内容 |
|---|---|
| 合言葉 | 空ならパブリック。設定すると入場に合言葉が要る |
| 定員 | 1ルーム 1〜60人 |
| ログイン必須 | ゲスト（未ログイン）を入れない |
| **VRChatに出す** | 上記②。ONは1つだけ |

βテスト中は「合言葉つき」で立てて、テスターにだけ伝える運用になると思います。
その間もVRChat連携はONにできるので、**合言葉つきイベントの人もVRC客席に出ます**。
そこは意図どおりで問題ないか、気になるようでしたら教えてください。
