## 一言でいうと

ブラウザ会場（https://allverse.onrender.com）で、**イベントを立ててから閉じるまでの動員を
記録する機能を実装しました**。ピーク同接・累計人数・滞在時間が出ます。

これを PORTAL の記事・イベント総目録に載せたいので、**そちらから取りに来てもらう形**の
APIを用意しました。**そちらのコードはまだ何も変えていません。** 取り込むかどうか、
取り込むならどう入れるかを決めてください。

---

## なぜ「取りに来てもらう」形にしたか

方式は3案あり、**案1（こちらがAPIを出し、PORTAL側が取りに来る）**を採りました。

| 案 | 内容 | 判断 |
|---|---|---|
| **1（採用）** | こちらがAPIを公開し、PORTALが取りに来る | **本番Supabaseの書き込み鍵をRenderに置かなくて済む。** VRChat連携と同じ考え方 |
| 2 | こちらがSupabaseに直接書きに行く | PORTAL側は無改修で済むが、正本DBの書き込み権限を外に出すことになる |
| 3 | 両方 | 作るものが増える |

案2は「PORTALが何も変えなくていい」のが利点ですが、**ブラウザ会場は不特定多数が
繋ぐサービス**なので、そこに正本DBの書き込み鍵を置くのは避けました。
取り込みの工程（誰がSupabaseに入れるか）はそちらの都合で決めてください。

## APIの仕様

### エンドポイント

```
GET https://allverse.onrender.com/api/stats.json
Authorization: Bearer <STATS_TOKEN>
```

- **合言葉（`STATS_TOKEN`）が未設定の間、この口は開きません**（403）。使うと決まったら
  Render の環境変数に設定します。値は別途安全な経路で渡します
- CORSは許可済み（`Access-Control-Allow-Origin: *`）。ブラウザからでもサーバーからでも取れます
- クエリ: `?since=<UNIXミリ秒>`（それ以降に始まった開催だけ）／ `?limit=<件数>`（既定200）

### 返るもの

```jsonc
{
  "ok": true,
  "source": "allverse-web",
  "generatedAt": 1785439568054,
  "events": [
    {
      "runId": "evms7wp7sj-1785439568054", // 開催1回の識別子（これが主キー向き）
      "eventId": "evms7wp7sj",             // イベントの識別子
      "name": "WEEKENDS vol.12",
      "openedAt": 1785439568054,           // 立てた時刻（UNIXミリ秒・UTC）
      "closedAt": 1785443168054,           // 閉じた時刻。null なら開催中
      "live": false,
      "durationSec": 3600,

      "peak": 42,                          // ピーク同時接続
      "peakAt": 1785441000000,             // その時刻
      "unique": 87,                        // 累計ユニーク人数
      "entries": 103,                      // のべ入場回数
      "entriesLoggedIn": 61,               // うちログイン済み
      "entriesGuest": 42,                  // うちゲスト
      "nowInside": 0,                      // いま中にいる人数（開催中のみ意味を持つ）

      "avgConcurrent": 23.4,               // 平均同接（のべ滞在 ÷ 開催時間）
      "avgStaySec": 818,                   // 平均滞在
      "medianStaySec": 640,                // 滞在の中央値
      "maxStaySec": 3540                   // 最長滞在
    }
  ]
}
```

### 出さないもの

**訪問者ごとの行は返しません。** PORTALに必要なのは「ピーク・累計・滞在」であって
「誰が来たか」ではないと判断したためです。必要になったら相談してください。

メールアドレスもこちら側の記録に残していません（ハッシュ化しています）。

## 取り込み先の候補（そちらで判断してください）

こちらで見た限り、Supabaseの `events` テーブルに **`manual_metrics`（手入力の数値）** という
列があります。ここが自動化の受け皿になりそうに見えました。ただし
**PORTAL側の設計はそちらが正**なので、この見立ては参考程度に扱ってください。

決めてほしいのは次の3点です。

1. **取り込む工程を誰が持つか**（PORTALのビルド時に取りに来る／GitHub Actionsで定期取得／手動）
2. **どのテーブル・どの列に入れるか**（`manual_metrics` に混ぜるのか、専用の列/テーブルを足すのか）
3. **突き合わせのキー**。こちらの `runId` と PORTAL のイベントをどう対応づけるか
   （名前一致は事故るので、PORTAL側にこちらの `runId` を持つ列を足すのが安全だと思います）

## 注意点

- **開催中も取れます**（`live: true`）。値は途中経過なので、記事に載せるのは
  `closedAt` が入ってからにするのが安全です
- Render無料プランは15分アクセスが無いと寝ます。取りに来たとき初回だけ数十秒待たされることがあります
- 記録のズレは**最大1分**（サーバー再起動時の補正の粒度）
- **こちらの累計は「同じブラウザ・同じGoogleアカウントを1人」として数えています。**
  ブラウザを変えた同一人物は別人として数えられます。記事に書くときの表現に注意してください
- ⚠ **ブラウザに匿名の識別子を保存する仕様なので、公開前に規約への記載が必要です**（未着手）。
  PORTALで数字を公開するなら、そちらの規約・プライバシーポリシーとも整合を取る必要があります
