# 申し送り⑦: VRC客席の本人アバターに吹き出しを出します（`web[].c` を有効化）

作成: 2026-08-03 ／ 発行元: ALLVERSE WEB側 ／ 宛先: Unity/VRChat側（VERSE CITY2025）
種別: **Udon側の作業依頼**（返答⑤「Udon側（吹き出しTMP追加等）はこちらで対応します」を受けたもの）
※ presence の契約（v=1）は変えていないので、**スキーマ変更の事前共有には当たりません**（理由は下記）

---

## 一言でいうと

**YouTubeのコメントを、VRC客席の本人プロキシアバターの頭上に吹き出しで出したい。**

そのために **`presence.json` の `web[].c`（いままでOFFだった項目）をONにしました。**

- **presence の契約は変わりません。** `c` は v=1 の仕様書（`PRESENCE_SPEC.md` §2.2）に
  **最初から任意項目として載っているもの**です。**バージョンは上げません。フィールドも増やしません。**
- **Worker側の作業はゼロです。** Worker は `web[]` を素通しで `live.json` に載せているので、
  ONにした瞬間から `live.json` の `web[]` に `c` が付いて流れます。
- **そちらが何もしなければ、いままで通り動きます**（未知の項目を無視するだけ）。
  吹き出しを出したいなら、Udon側にTMPの追加が要ります。

---

## 経緯（なぜいま出すのか）

返答②の時点では「チャット吹き出しは当面やらない。位置連携を先に通す」で合意していました。
その位置連携が本番で通り、さらに **2026-08-03 の実配信で
「YouTubeのコメント → ブラウザ会場の本人アバターの吹き出し」が動きました。**

いまは **ブラウザ会場だけ吹き出しが出て、VRC客席のプロキシは黙っている**状態です。
エモート（ペンライト等）はもう両方に届いているので、
**同じ人が、VRCでは振っているのに喋らない**、という絵になっています。ここを揃えたい。

## 決めたこと（WEB側の判断）

Workerの担当がこちらに移ったので、下記はこちらで決めました。異論があれば言ってください。

### 決定1: 経路は `presence.json → live.json` の素通し。Workerで別口は作らない

`live.json` 側に新しい枠を作る案もありましたが、やめました。

- `c` は**もともとv=1に定義されている**ので、使うのに協議も版上げも要らない
- Worker は `web[]` を配列ごと素通ししている（`attachWebPresence`）。**手を入れずに通る**
- 発言と座標が**同じ人の同じ1件**として届く。別口にすると突き合わせが要る

### 決定2: ★ **VRCへ出すのは「YouTube由来の発言」だけ。ブラウザ会場の独自チャットは出さない**

これが今回いちばん重要な判断です。

`presence.json` も `live.json` も**認証なしで誰でも取れる公開URL**です。
ここに発言本文を載せるということは、**その場にいない人にも読める**ということです。

| 発言の出どころ | VRCへ出すか | 理由 |
|---|---|---|
| **YouTubeのコメント** | **出す** | **元から公開の場での発言**。YouTubeのチャット欄を開けば誰でも読める。公開URLに40文字・30秒だけ再掲しても、新しく漏れるものが無い |
| **ブラウザ会場の独自チャット** | **出さない** | **会場に入った人どうしの会話**。公開の場で言ったつもりが無い。ここを載せると「入場者だけの会話」が公開URLから全部読めるようになる |

**この線引きはWEB側で実装します。** そちらは届いた `c` を出すだけで構いません。
（`c` が付くのは YouTube由来の発言だけになります）

なお `yt[]`（YouTube発言者リスト）は**引き続き常に空**です。
**合言葉でアバターと結びついた人**だけが `web[].c` として流れます。
結びついていない視聴者の発言は、VRCには出しません（出す先のアバターが無いため）。

### 決定3: ブラウザ会場とVRCで、出る条件を揃える

ブラウザ会場で吹き出しが出た発言は、VRCにも `c` として出ます。
「片方だけ出る」状態を作らないためです。

⚠ 本人設定の「コメントで自分のアバターを動かさない」は**エモート専用**です。
これをOFFにしている人でも**吹き出しは出ます**（ブラウザ会場と同じ挙動）。

## そちらが読む仕様

### 形

```json
{ "rm":1, "n":"なまえ", "x":-209.0, "z":-77.0, "r":90,
  "av": { "h":"bob", "ht":"mid", "...":"..." },
  "c": ["この曲すき！", 1785700123] }
```

| | |
|---|---|
| `c[0]` | 本文。**最大40文字でカット済み**（こちら側で処理済み。そちらで更に切るのは自由） |
| `c[1]` | 発言時刻（**秒**。ミリ秒ではない） |

### 読み方（`em` と同じ考え方です）

- **直近30秒以内に発言した人にだけ `c` が付きます。** 30秒を過ぎると**項目ごと消えます**
- **「消して」という合図は送りません。** `c` が無い＝出すものが無い、と読んでください
- 同じ人が続けて喋ると `c[1]` の秒が変わります。**新しい方に差し替え**てください
- `live.json` は5秒おきなので、**発言から最大5秒遅れて**出ます

### 表示時間はそちらで決めて構いません

ブラウザ会場は**既定8秒**です（4/6/8/12/20秒・消さない から各自選べる）。
**VRCも8秒を推奨**します。ただし `c` 自体が30秒で消えるので、それ以上は延ばせません。

### ⚠ 身長 `ht` と一緒に拡縮してください

申し送り⑥で入れた `av.ht`（small/mid/big）に対応するなら、
**吹き出しもアバターと一緒に拡縮**してください。ブラウザ側はそうしています。
頭の上に固定した吹き出しが、小さい人だと頭にめり込みます。

---

## ⚠ 正直に伝えておく弱点（NGワード・削除まわり）

**こちら側でNGフィルタはかけていません。** 通っているのは
**YouTube側のモデレーションを通過した発言**だけ、という前提に乗っています。

そのうえで、**こちらでは追いきれない穴が1つあります**:

> **取得した後にYouTube側で消された発言は、こちらは知りようがありません。**
> 荒らしのコメントが配信者に消されても、**VRCとブラウザの吹き出しには最大30秒残ります。**

30秒で自然に消えるので実害は小さいと踏んでいますが、
**そちらで追加のフィルタを入れるかは、そちらの判断でお願いします**（入れなくても構いません）。
こちら側にもワードのフィルタを足すべきだと思うなら、言ってください。実装します。

## サイズへの影響

**実測しました（2026-08-03）。結論: 最悪ケースでも 19.1KB で、30KB上限に収まります。**

上限いっぱいの**60人を実際に入場させ、全員をYouTubeと結びつけ、
全員が40文字の発言＋エモートを同時に出している状態**を作って測った値です。

| | |
|---|---|
| 実測 | **19,599バイト（19.1KB）** |
| 内訳 | 60人全員に `c` あり・`em`/`emt`/`emd` あり |
| 名前ぶんの上振れ | 実測時は自動名（「ゲスト003」）だったので、12文字の日本語名なら **+約1.4KB → 約20.5KB** |
| 上限 | 30KB（`PRESENCE_SPEC` の目安） |

余裕は**約9KB**です。`web[]` は60人でトリムしているので、これ以上は増えません。

5. 上の「決めたこと」に異論があれば教えてください。特に**決定2（会場チャットは出さない）**は
