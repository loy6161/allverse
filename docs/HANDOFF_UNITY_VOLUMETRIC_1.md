## 3. 動かなかったところと、その理由

**立体が1画素も出ない。**「5方向すべてが内側と言う点」が存在しない。

調べて分かったこと:

### ① ストリップのレンジが全域（−1〜1）になっている

仕様 §7 は「`Tight Bounds` が false でも切り詰めは働いている。前後が ±0.45 m ＝
volume 座標で 0.275〜0.725 なので、Left / Right のタイルは横方向が全体の約45%に
切り詰められている」と書いている。

**だが、もらったフレームのストリップには全域が載っている。**
ドライバが送信マテリアルの `_RangeMin/_RangeMax` だけ更新して、ストリップには
既定値が載った、という筋を疑っている。

### ② 実際のタイルを測ると、切り詰めが効いている形跡がある

深度タイルの中で人物が占める位置（タイル内の中心 x、0〜1）:

| タイル | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 中心x | 0.42 | 0.28 | 0.49 | 0.51 | 0.80 |
| 幅 | 319 | 89 | 104 | 104 | 153 |

⚠ **Front と Back は同じ x 軸を反対から見る**ので、中心は対称（0.42 なら 0.58）に
なるはず。実測は 0.28 で合わない。**タイルごとに違う切り詰めがかかっている**と考えるのが自然。

### ③ 送信側の「軸の反転」は、レンジが全域だと効かない

`ALLVERSE_FramePack.shader` の `rescale_depth`:

```
if (reversedAxis) { float t = 1.0 - hi; hi = 1.0 - lo; lo = t; }
```

反転は **lo と hi の入れ替え**で実装されている。レンジが全域（lo=0, hi=1）だと、
入れ替えても同じ値なので**何も起きない**。

そのため Back / Left / Top の深度が Front と同じ向きのまま届き、
Front から見た表面（q.z=+0.26）と Back から見た表面（q.z=−0.28）が交わらない
＝内側の点が存在しない。

受信側で反転を補うスイッチ（「向きを補う」）を付けて試したが、
①②が未解決なので、それだけでは出なかった。

## 追記③（2026-08-08・原因を数値で特定）

### 結論: **深度が2mの箱で正規化されていない。**

`PackedFrame_sample.png` の深度タイルから、被写体が使っている値の幅を測った:

| ビュー | 深度タイルの値の幅 |
|---|---|
| Front | 0.498 〜 0.882 |
| Back | 0.435 〜 0.827 |
| Left | 0.282 〜 0.769 |
| Right | 0.282 〜 0.769 |
| Top | 0.282 〜 0.976 |

送信側の `rescale_depth` は **被写体の箱（RangeMin/Max）で正規化してから 0.02〜0.98 に載せる**
ので、被写体は必ず 0.02〜0.98 いっぱいに広がるはず。**広がっていない。**

さらに、Front と Back は同じ z 軸を反対から見るので、**同じ表面の値の和は一定**になる:

- Front + Back = 1.32（0.882+0.435、0.498+0.827 とも）
- Left + Right = 1.05

**軸によって定数が違う。** 箱は立方体なのでカメラの距離が同じなら一致するはずで、
これは **深度の 0〜1 が「2mの箱」ではなく「カメラの near〜far」で決まっている**ことを示す。

実測から逆算すると、Front の深度 0〜1 は **箱の約2.6倍の奥行き**に対応していた。

### 心当たり（そちらのコードを読んだ範囲）

1. `ALLVERSEVolumetricPoCTools.cs` の中に、撮影カメラの設定が**3種類**ある
   - 1113行: `orthographic = false` / near 0.01 / far 5
   - 1333行: `orthographic = true` / size 1 / near 0.1 / far 2
   - `ALLVERSEVolumetricPoCBuilder.cs` 270行: `orthographic = true` / size 1 / near 0.5 / far 2.5
   **実際に使われているのはどれか。** far−near が 2 でないと、深度の 0〜1 が箱と一致しない
2. `linear_depth` は `UNITY_REVERSED_Z` の反転だけで、**`Linear01Depth` を通していない**。
   透視投影のカメラだと深度は非線形（1/z）のままになる

### こちらの状態

- 識別ストリップ・切り詰めの逆算・タイルの読み取りはすべて動く（そちらの値と完全一致）
- 深度マップの表示（`?mode=depth`）で、5方向のシルエットがきれいに出る
- **立体の再構成だけが出ない。** 上の理由で、5方向の表面が同じ場所を指さないため

**深度が箱で正規化されて届けば、こちらの実装はそのまま動く見込み。**
